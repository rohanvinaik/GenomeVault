## Executive Summary

GenomeVault's probabilistic alignment system implements a **"data poisoning for defense"** security model where **making stolen data untrustworthy is more effective than preventing theft**.

**Key Insight**: Even if an adversary breaks SHA-256 encryption and obtains FASTQ alignment data, they cannot determine which positions contain injected biological uncertainty vs. real genomic variation.

**Quantitative Guarantee**:
- 95-99% similarity across all users (high utility for legitimate analysis)
- 1-5% unknowable uncertainty (renders stolen data nearly useless)
- Exponential adversarial search space: 4^(uncertain_positions) possible interpretations

### Traditional Security Model

**Goal**: Prevent adversary from obtaining data

**Problem**: Once encryption is broken, data is fully compromised

```
Traditional: [Encrypted Data] --[Break SHA-256]--> [Fully Usable Data]
                                      ↓
                            Complete Privacy Loss
```

### GenomeVault Security Model

**Goal**: Make obtained data untrustworthy and nearly useless

**Advantage**: Even after breaking encryption, adversary gains minimal actionable information

```
GenomeVault: [Encrypted Data] --[Break SHA-256]--> [Data with Unknown Noise]
                                                            ↓
                                                   Exponential Ambiguity
                                                            ↓
                                              Nearly Zero Actionable Information
```

## How It Works: The Byzantine Consensus Middleman

### The Core Mechanism

**Traditional FASTQ Alignment**:
```
FASTQ fragments (random order)
        ↓
Align to hg38 reference
        ↓
Ordered genome (PROVABLY linked to hg38)
```

**GenomeVault Probabilistic Alignment**:
```
FASTQ fragments (random order)
        ↓
Align to Byzantine consensus (hg38 + GRCh37 + T2T-CHM13 with positional uncertainty)
        ↓
Ordered genome (CANNOT prove which reference(s) used)
        ↓
Differential encoding (k=3 anonymity)
        ↓
HDC + ZK + PIR (existing GenomeVault)
```

**Key Point**: The consensus reference acts as a **"blind middleman"** - it enables fragment ordering (necessary for genomic analysis) WITHOUT creating a deterministic, reversible mapping to specific public references.

**Problem for Thief**:
1. The money looks valuable (95% is real)
2. You can't tell which bills are counterfeit
3. You can't use the money without risk
4. Testing every bill is prohibitively expensive
5. The uncertainty makes the entire haul nearly worthless

**GenomeVault Application**:
- 95-99% of consensus positions are "real" (match one or more public references)
- 1-5% have injected biological uncertainty (IUPAC ambiguity codes, positional noise)
- Adversary cannot determine which positions are uncertain
- Testing requires re-sequencing or expensive validation
- **Result**: Stolen alignment data provides minimal insight

### Uncertainty Injection Parameters

**Consensus Construction**:

```python
# Per-base decision across N=3 references (hg38, GRCh37, T2T-CHM13)
def build_consensus(position):
    bases = [hg38[position], grch37[position], chm13[position]]

    if all_agree(bases):
        return bases[0]  # High confidence
    elif two_agree(bases):
        # Inject uncertainty with exponential decay
        certainty = base_confidence * (10^-6)^consecutive_disagreements
        if certainty < threshold:
            return IUPAC_ambiguity_code(bases)  # e.g., 'R' for A/G
        else:
            return majority_vote(bases)
    else:
        # Maximum uncertainty
        return 'N'  # Complete ambiguity
```

**Resulting Distribution** (typical for chr22):
- High confidence: ~94% (all references agree)
- Low confidence: ~5.6% (2 references agree, injected uncertainty)
- Ambiguous (IUPAC): ~0.4% (complete disagreement)

## Hierarchical Mismatch Classification

### Critical Distinction: SNPs vs. Structural Variants

**SNP (Single Nucleotide Polymorphism)**: ONE base differs, neighbors match

```
Position:  1000  1001  1002  1003  1004
Reference: A     C     G     T     A
Query:     A     T     G     T     A
Match:     ✓     ✗     ✓     ✓     ✓

Result: SNP at position 1001 (isolated mismatch)
```

**Consecutive Mismatches**: Multiple adjacent positions differ

```
Position:  1000  1001  1002  1003  1004
Reference: A     C     G     T     A
Query:     A     T     C     G     A
Match:     ✓     ✗     ✗     ✗     ✓

Result: 3 consecutive mismatches (positions 1001-1003)
```

### Statistical Interpretation

| Pattern | Frequency | Biological Interpretation | Action |
|---------|-----------|---------------------------|--------|
| **1 mismatch** (neighbors match) | ~10^-6 | **Normal SNP** - expected biological variation | SNP database lookup |
| **2 consecutive** | ~10^-12 | **Rare but possible** - two adjacent SNPs (linkage) | Statistical test |
| **3 consecutive** | ~10^-18 | **HIGHLY SUSPICIOUS** - likely sequencing error | Flag for QC review |
| **4+ consecutive** | Common | **STRUCTURAL VARIANT** - indel/duplication/transposition | Trigger SV pipeline |

### The "Peak Suspicion" Point

**Key Insight**: 3 consecutive mismatches is the "peak suspicion" point.

- **1-2 consecutive**: Expected biological variation
- **Exactly 3 consecutive**: Essentially impossible biologically (p < 10^-18)
  - **Interpretation**: Likely sequencing error (adapter contamination, PCR artifact, base quality collapse)
  - **Action**: Flag for quality control review

- **4+ consecutive**: Back to common!
  - **Interpretation**: Legitimate structural variation
  - **Examples**:
    - Deletions (ref has sequence, query doesn't)
    - Insertions (query has sequence, ref doesn't)
    - Duplications (copy number variation)
    - Transpositions (mobile element insertions)
  - **Action**: Trigger comprehensive SV detection pipeline

### Implementation

```python
def classify_mismatch_pattern(consecutive_mismatches: int) -> str:
    """
    Classify mismatch pattern with correct biological interpretation.

    CRITICAL: 3 consecutive is sequencing error, 4+ is structural variant.
    """
    if consecutive_mismatches == 0:
        return "PERFECT_MATCH"
    elif consecutive_mismatches == 1:
        return "ISOLATED_SNP"  # Normal (~10^-6 frequency)
    elif consecutive_mismatches == 2:
        return "TWO_ADJACENT_SNPS"  # Rare but biological (~10^-12)
    elif consecutive_mismatches == 3:
        return "LIKELY_SEQUENCING_ERROR"  # Highly suspicious (~10^-18)
    else:  # 4+
        return "STRUCTURAL_VARIANT"  # Common - trigger SV detection

def compute_certainty(consecutive_mismatches: int) -> float:
    """
    Certainty with structural variant awareness.

    4+ consecutive returns HIGHER certainty than 3 consecutive
    because it's likely legitimate biological variation.
    """
    if consecutive_mismatches == 0:
        return 1.0  # Perfect match
    elif consecutive_mismatches == 1:
        return 1e-6  # SNP frequency
    elif consecutive_mismatches == 2:
        return 1e-12  # Rare adjacent SNPs
    elif consecutive_mismatches == 3:
        return 1e-18  # Sequencing error (minimum)
    else:  # 4+
        return 0.5  # Structural variant (moderate certainty, triggers SV pipeline)
```

## Purpose: Privacy-Preserving Fragment Ordering

### The FASTQ Problem

**FASTQ files contain**:
- Fragmented sequencing reads (50-300bp chunks)
- Random order (no positional information)
- Cannot be analyzed without ordering

**Example**:
```
Read 1: ATCGATCGATCG... (from chr22:16,050,000)
Read 2: GCTAGCTAGCTA... (from chr22:16,150,000)
Read 3: TGATGATGATGA... (from chr22:16,075,000)

Without reference alignment: Cannot determine order or positions!
```

### Traditional Solution: Direct Reference Alignment

```
FASTQ reads → Align to hg38 → Ordered genome

Problem: Creates PROVABLE link to hg38
- Alignment coordinates are deterministic
- Can be reversed: "Position 16,050,000 on hg38"
- Privacy leak: Adversary knows exact reference used
```

### GenomeVault Solution: Byzantine Consensus Middleman

```
FASTQ reads → Align to Byzantine consensus → Ordered genome

Advantage: Fragment ordering WITHOUT provable reference linkage
- Consensus is a weighted combination of hg38 + GRCh37 + T2T-CHM13
- Positional uncertainty injected at disagreement sites
- Cannot reverse-engineer which reference(s) contributed
- Cannot prove alignment came from specific public data
```

**Analogy**: The consensus reference is like a "blind courier" - it carries your message (fragment order) but doesn't reveal the sender (reference provenance).

## Security Guarantees

### What GenomeVault Protects Against

1. **Reference Provenance Attacks**
   - Adversary cannot determine which public reference(s) were used
   - No deterministic mapping to hg38, GRCh37, or T2T-CHM13

2. **Alignment Reverse Engineering**
   - Cannot reverse-engineer original FASTQ alignment
   - Uncertainty creates exponential search space (4^100,000 interpretations)

3. **Data Re-identification**
   - Even with stolen alignment data, cannot link to individual
   - k=3 differential encoding adds additional anonymity layer

4. **Partial Information Leakage**
   - 95-99% correct data is NOT enough for actionable insights
   - 1-5% uncertainty contaminates the entire dataset

### What GenomeVault Does NOT Protect Against

1. **Complete Consensus Disclosure**
   - If adversary obtains the EXACT consensus reference used, they can re-align
   - **Mitigation**: Each user gets a slightly different consensus (random seed)

2. **Known Plaintext Attacks**
   - If adversary has user's raw FASTQ + GenomeVault output, could correlate
   - **Mitigation**: Never disclose raw FASTQ after GenomeVault encoding

3. **Side-Channel Attacks**
   - Timing attacks, power analysis (hardware-level)
   - **Mitigation**: Constant-time operations where cryptographically necessary

## Conclusion

GenomeVault's probabilistic alignment system implements a novel **"data poisoning for defense"** security model that recognizes a fundamental truth: **preventing theft is hard, making stolen data useless is achievable**.

By introducing 1-5% unknowable positional uncertainty into a Byzantine consensus reference, the system maintains 95-99% utility for legitimate genomic analysis while rendering stolen alignment data nearly worthless to adversaries.

The **hierarchical mismatch classification** (1-nt SNPs, 2-nt rare, 3-nt error, 4+ SV) ensures biological accuracy while the **Byzantine consensus middleman** enables FASTQ fragment ordering without creating provable linkages to public references.

**Key Takeaway**: You don't need perfect secrecy. You need enough uncertainty that stolen data provides nearly zero actionable information.
